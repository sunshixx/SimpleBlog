# 2026-08-21

## 博客 v2.0：JSON 存储 → Markdown 文件存储 + 图片库

### 改造背景
原 `db/articles.json` 单文件存全部文章（已膨胀到 33KB），用户希望改用更轻量的数据库方案。

### 方案
**采用每篇文章一个 .md 文件 + YAML frontmatter**（零依赖、最轻量）：
- `db/articles/{id}.md` 每篇一个文件，frontmatter 存元数据（id/title/category/author/date/time/weekday/subscription/comments/tags/summary），正文为 Markdown
- 启动时全量扫 `db/articles/` 目录构建内存索引，CRUD 同步到对应 .md 文件
- 优点：备份/git diff 看得见、JSON 永不膨胀、单篇损坏不连累其他

## v2.1：去 AI 味 UI + 粘贴板支持 + 上传任意路径 + 发布时归档

### 用户反馈
1. admin 编辑器图片库 UI 太花哨（彩色按钮、modal 弹窗、grid 卡片）—— AI 味重，跳脱原生 LWN.net 审美
2. 写作时不希望每次都先上传图片再写 markdown，希望支持粘贴板
3. 上传图片不应固定 picture 路径；上传可以是任意路径，发布时再统一拷贝到 picture/ 归档

### 改造方案

**UI 改造（去 AI 味）**：
- 删除 modal-mask/modal-box/pic-card/pic-grid/editor-toolbar/tb-btn 等所有花哨 CSS
- 改成 LWN 原生审美：朴素的 `<details class="pic-section">` 折叠区，里面是 form 风格的 input + 按钮（用 var(--ButtonColor) 桃色按钮，var(--FormBG) 灰底）
- 删除 emoji 图标

**粘贴板支持**：
- textarea 监听 paste 事件
- 检测 clipboardData.items 中的 image/*
- 自动上传到 picture/（粘贴路径无机会选路径，直接归 picture）
- 上传成功后在光标处插入 `![name](picture/xxx.png)`
- 用文件名 `paste-<timestamp>.<ext>`

**上传任意路径**：
- 上传表单加路径输入框（默认 "picture"）
- POST /api/pictures 接受 multipart 表单字段 `path`，保存到 ROOT 内任意相对目录
- `safeRelativeDir()` 防目录穿越（拒绝 ../、绝对路径）
- 返回 `ref` 字段是相对于 ROOT 的 markdown 引用路径（如 `images/foo.png`）

**发布时归档（核心新功能）**：
- `archivePicturesInContent(content)` 扫描 markdown 中所有本地图片引用
- 跳过 `picture/` 开头（已归档）、外链（http/https/data:）、绝对路径（/开头）
- 其他的本地相对路径：调用 `archivePictureRef(relPath)` 物理拷贝源文件到 picture/ 下，返回新引用
- 重写 markdown 中的引用为 `picture/<filename>`
- 同名自动加序号（`foo.png` → `foo_1.png`）
- 源文件保留（拷贝而非移动）
- 在 `createArticle` 和 `updateArticle` 中都调用

### API 变化
- `GET /api/pictures?dir=xxx` 可列出任意 ROOT 内目录的图片
- `POST /api/pictures` 接受 multipart 字段 `path`，指定保存目录
- 响应新增 `ref` 字段（markdown 引用路径）

### Bug 修复
- `handleAPI(req, res, pathname, method)` 缺少 `urlObj` 参数 → 改为 `handleAPI(req, res, pathname, method, urlObj)`
- `deletePicture` / `deleteArticleFile` 在 sandbox trash hook 报错时，以"文件最终不存在"为准判断成功

## v2.3.1：路径检查 Windows 兼容性 bug 修复

### 问题
v2.3 中把 `serveStatic` 改成 `path.resolve(ROOT, pathname)`，但在 Windows 上 `path.resolve(ROOT, '/index.html')` 把 `/index.html` 当作绝对路径，**绕过 ROOT**，结果 `C:\index.html`，导致所有页面都 403。

### 修复
- 改用 `path.resolve(path.join(ROOT, pathname))`：
  - `path.join(ROOT, '/index.html')` = `C:\Users\DP\...\blog\index.html`（join 把前导 / 当片段）
  - `path.resolve` 拿到标准绝对路径
  - startsWith(ROOT+sep) 严格检查防 ../ 逃出

### 教训
- **Windows 路径陷阱**：`path.resolve(ROOT, '/abs/path')` 不会用 ROOT 作为基准，会把 `/abs/path` 当作绝对路径。必须用 `path.join` 先拼起来。
- 这类 bug 在 Linux/Mac 上不会复现（POSIX 路径语义不同），所以本地开发可能测不出来，要在 Windows 上验。

### 验证结果
- 全部正常页面（/ /index.html /admin.html /article.html /tags.html /search.html /about.html /css/* /js/* /picture/*） → 200 ✓
- 路径穿越（/..%2Fconfig.json /picture/..%2F..%2Fconfig.json 等） → 403 ✓
