# Conplat 命令行编程手册 V2.0 学习笔记

## 1. 概述
- 本手册介绍 Conplat 平台标准命令行（CLI）的开发方法，涵盖命令行语法、视图、关键字类型、cmdkey、注册命令接口、备份模式、前后台命令、隐藏命令、全局命令及常见问题等。
- 命令行通过 console、telnet、SSH 等方式接入，提供分层视图、关键字自动补齐、帮助信息等功能。
- 命令行服务进程名为 **vtysh**，设备启动时由 startup 进程调用 `/etc/init.d/vtysh` 启动；进入 shell 模式可执行 `ps aux | grep vtysh` 查看进程号。

---

## 2. 命令行基本概念

### 2.1 命令行与命令行进程
- 命令行（CLI）是基于命令的配置管理手段，用户在提示符下输入命令对设备执行配置管理。
- 标准命令行具有关键字自动补齐、关键字与参数均带帮助信息、命令按视图分层等特点。
- 通过 console 开发人员模式或远程诊断进入 shell 模式后，不属于标准命令行界面。

### 2.2 命令原型
- 由 **关键字**（固定单词）和 **参数**（可变值）按一定顺序组合而成的字符串表达式。
- 理想组织方式：`功能关键字区1 参数区1 关键字区2 参数区2 ...`
- 示例：`radius (primary|secondary) server-ip A.B.C.D source-ip A.B.C.D [port<1-65535>] key STRING [timeout<1-10>] [retransmit<1-20>]`

### 2.3 参数表达语法
| 符号 | 含义 | 示例 |
|------|------|------|
| `[]` | 可选，不支持与 `|` 嵌套 | `[password STRING]` |
| `()` + `|` | 多选一，必须与 `|` 配合使用 | `(deny|permit)` |
| `{}` | 可出现一次或多次 | `{STRING}` |
| 组合嵌套 | 三者可任意组合嵌套 | `[(deny|permit)]` |

### 2.4 参数类型（常用）
| 参数类型 | 写法 | 含义 | 对应标准类型 |
|----------|------|------|--------------|
| 整数 | `<min-max>` | 输入指定范围内的整数 | 整型 |
| 整数范围 | `INTRANGE` | 一段整数范围 `min-max` | 整数范围 |
| 整数域 | `INTDOMAIN` | 逗号分隔的多段整数范围 | 整数范围 |
| IPv4 地址 | `A.B.C.D` | IPv4 地址 | IPv4 |
| 带掩码 IPv4 | `A.B.C.D/M` | 带掩码 IPv4 地址 | IPv4 |
| IPv6 地址 | `X:X::X:X` | IPv6 地址 | IPv6 |
| MAC 地址 | `XX:XX:XX:XX:XX:XX` | MAC 地址 | MAC |
| 字符串 | `STRING` | 除空格和 `"&<>` 外任意字符 | 字符串 |
| 字符串 | `WORD` | 除空格外任意字符 | 字符串 |
| 任意多串 | `.LINE` | 任意字符，只能放命令末尾 | 字符串 |
| 日期 | `YYYY-MM-DD` | 年-月-日 | 日期 |
| 时间 | `HH:MM:SS` / `HH:MM` | 时分秒 / 时分 | 时间 |
| 接口动态帮助 | `IFNAME` / `IFINDEX` | 匹配接口名，下发名称或索引 | 字符串 |
| 动态帮助 | `ENUMNAME` / `ENUMNUMBER` / `ENUMNEW` | 匹配动态帮助内容，下发名称/ID | 字符串 |

### 2.5 参数默认下发规则
- **参数**（可变部分）**总是下发**到执行函数的 `argv`。
- **关键字**（固定部分）默认**不下发**，除非：
  - 被 `()` 或 `{}` 包裹且位于 `|` 分隔的某个子区间内，则该子区间内**只下发第一个关键字**。
- 可通过 `cmdkey` 手动控制每个位置是否下发。

**示例理解：**
- `interface IFNAME`：`interface` 是裸露关键字不下发，`IFNAME` 是参数下发。
- `service forbid (ping|telnet|ssh|http|https|all)`：`service forbid` 不下发，括号内每个选项作为独立子区间，选中的选项（如 `ping`）下发。
- `service forbid (service1 service2 IFNAME service3|service4)`：左子区间内只下发第一个关键字 `service1`，`IFNAME` 参数下发，`service2`/`service3` 不下发。

### 2.6 cmdkey
- `cmdkey` 是一个字符数组，与命令原型中的每个元素（关键字和参数）一一对应。
- 元素为 `'-'` 表示不下发；为其他字符（如 `'C'`、`'I'`）表示下发，该字符会存入 `argk` 供执行函数判断用户选择了哪个选项。
- 在命令执行函数中通过 `switch(argk[i])` 区分不同选项分支。
- 在动态帮助函数中通过参数 `key`（即 cmdkey 中对应元素）区分是对哪个关键字显示可选参数。
- 若命令注册时 `cmdkey` 设为 `NULL`，则按默认下发规则下发。

## 3. 注册视图

### 3.1 视图概念
- 命令行界面分为若干视图，通过在视图下执行切换命令进入不同视图，当前视图决定可使用的命令。
- 公共视图列表：
| 视图名称 | 访问方法 | 提示符 | 说明 |
|----------|----------|--------|------|
| 用户视图 | 登录后首先进入 | `<DPTECH>` | 执行不需保存配置的命令（show、ping 等） |
| 配置视图 | 用户视图执行 `conf-mode` | `[DPTECH]` | 设备全局配置（路由、telnet 等） |
| 接口视图 | 配置视图通过 `interface` | `[DPTECH-meth0_0]` | 配置各种接口 |
| 开发人员视图 | 配置视图通过 `deve` | `[DPTECH-Developer]` | 开发人员调试命令 |
| Shell 视图 | 开发人员视图通过 `_shell` | `[DPTECH-Developer-Shell]` | 隐藏带密码命令，密码 `hzdp2015` |

### 3.2 数据结构定义
```c
struct cmd_node {
    enum node_type node;        // 视图枚举值（房间号）
    char *prompt;               // 视图提示符，如 "[%s]" 或 "[%s-%s]"
    int vtysh;
    int (*func)(struct vty*);   // vtysh 进程配置概览回调
    cmd_summ_func cfg_func;     // daemon 进程配置概览回调
    vector cmd_vector;          // 当前视图所有命令集合
    int (*pf_before_exit)(struct vty*); // 退出前执行函数，返回非0取消退出
    int (*check_node)(struct vty*, void*); // 视图合法性检查回调
    int (*show_config_callback)(struct vty*); // 显示当前视图配置回调
};

enum node_mode_type {
    vty_node_no_change,   // 视图模式不改变
    vty_node_forward,     // 视图模式前进一步
    vty_node_backoff,     // 视图模式后退一步
    vty_node_to_view      // 视图模式退到 view_mode
};

typedef enum node_type {
    AUTH_NODE, VIEW_NODE, ENABLE_NODE, CONFIG_NODE, DEBUG_NODE,
    KEYCHAIN_NODE, PREFIX_GROUP_NODE, ZEBRA_NODE, RIP_NODE, RIPNG_NODE,
    /* ... 各模块视图 ... */
    NODE_MAX
} E_TYPE_E;
```

### 3.3 常用接口列表
| 接口 | 说明 |
|------|------|
| `vtysh_install_node(node, func, pf_before_exit)` | 在 vtysh 进程注册一个普通视图 |
| `vtysh_install_node_special(node, func, pf_before_exit, check_node, data, level, show_config_callback)` | 注册带合法性检查的视图 |
| `cmd_daemon_install_node(node, cfg_func, data)` | 在后台 daemon 进程注册视图 |

### 3.4 示例：注册"用户组视图" GROUP_NODE
**步骤一：在 `enum node_type` 中定义视图枚举值**
```c
typedef enum node_type {
    CLASS_MAP_NODE,
    GROUP_NODE,      // 新增用户组视图
    RTPOLICY_NODE,
    NODE_MAX
};
```

**步骤二：定义视图结构体**
```c
struct cmd_node group_node = {
    GROUP_NODE,      // 视图枚举值
    "[%s-%s]"        // 提示符格式，如 [DPTECH-aaa]
};
```

**步骤三：注册进入视图命令**
```c
VTY_DEF_VIEW_BACKUP(
    user_local_group_func,      // 执行函数名
    user_local_group_cmd,       // 命令全局变量名
    "local-group STRING",       // 命令原型
    NULL,                       // cmdkey，用默认规则
    "Create local groups\n"
    "Group's name\n",           // 帮助信息
    GROUP_NODE)                 // 进入的目标视图
{
    vty_set_node_prompt(vty, argv[0]);   // 设置提示符，如 [DPTECH-111]
    vty_set_index(vty, strdup(argv[0])); // 保存视图私有数据，退出时释放
    return CMD_SUCCESS;
}

// 在配置视图下安装进入命令
install_element(CONFIG_NODE, &user_local_group_cmd);
```

**步骤四：调用安装视图函数**
```c
vtysh_install_node(&group_node, NULL, node_exit_call_back);
```

## 4. 注册命令

### 4.1 命令宏定义列表
| 宏 | 使用说明 |
|----|----------|
| `DEFUN` | 普通命令，正常备份，不带动动态帮助，不发后台 |
| `DEFUNHELP` | 带动态帮助函数，正常备份，不发后台 |
| `DEFUN_NOBACKUP` | 不备份，可带动态帮助，不发后台 |
| `DEFSH` | 发往指定 daemon 执行，不备份 |
| `DEFSHHELP` | 发往指定 daemon 执行，且带动态帮助 |
| `DEFSH_NOBACKUP` | 发往后台 daemon 执行，不备份，可带动态帮助 |
| `VTY_DEF_VIEW` | 普通进视图命令，无执行函数，不备份 |
| `VTY_DEF_VIEW_CMD` | 进视图命令，有执行函数，不备份 |
| `VTY_DEF_VIEW_BACKUP` | 进视图命令，有执行函数，且备份 |
| `DEFUN_CUSTOM_BACKUP` | 自定义备份模式（主备/VSM/静默双机） |
| `DEFSH_CUSTOM_BACKUP` | 自定义备份模式，发往 daemon |

### 4.2 命令结构体 `struct cmd_element`
```c
struct cmd_element {
    s8 *string;       // 命令原型
    s32 (*func)(struct cmd_element*, struct vty*, int, char**, char*); // 执行函数
    s8 *doc;          // 帮助信息
    s32 (*func_help)(char, struct vty*, vector); // 动态帮助函数
    s32 daemon;       // 所属 daemon ID（-1 表示前台执行）
    s32 node_mode;    // 视图操作模式
    s32 backup_mode;  // 备份模式
    enum node_type forward_node; // 进视图命令的目标视图
    struct cmd_parse_node_s *graph_head; // 解析图
    s8 *config;
    vector subconfig;
    s32 invisible;    // 是否隐藏
    s32 pawdflag;     // 是否需要密码
    s8 *passwd;       // 密码
    u_char attr;      // 命令属性
    s32 confirm;      // 是否需要确认
    s8 *cmdkey;       // 关键字下发标志数组
    s32 rollback;     // 配置回滚标志
    s32 vsystype;     // 支持的虚拟系统类型
    s32 module;       // 所属模块
    u8 bitmap_if_types[...]; // 接口类型位图
};
```

> 一句话：`cmd_element` 就是一条命令的"户口本"，记录命令长什么样、谁来执行、是否发后台、是否隐藏等所有元信息。`DEFUN` 系列宏就是帮你快速创建并填充这个结构体的"自动填表机"。

### 4.3 常用注册接口
| 接口 | 说明 |
|------|------|
| `install_cmd(ntype, cmd, cmd_attr)` | 注册指定虚拟系统类型的普通命令（推荐） |
| `install_element(ntype, cmd)` | 注册普通命令（仅公共虚拟系统，建议逐步替换为 `install_cmd`） |
| `install_hidden_cmd(ntype, cmd, cmd_attr)` | 注册隐藏命令（`?` 不显示，Tab 不补齐） |
| `install_hidden_element(ntype, cmd)` | 注册隐藏命令（仅公共虚拟系统） |
| `install_global_cmd(cmd, cmd_attr)` | 注册可在任意视图执行的命令（所有 show 命令必须用此） |
| `install_global_show_command(cmd)` | 注册任意视图可执行命令（仅公共虚拟系统） |
| `install_interface_cmd(ntype, cmd, cmd_attr, ...)` | 注册接口视图下支持指定接口类型的命令 |

### 4.4 动态帮助命令
- 使用 `DEFUNHELP` 等带动态帮助函数的宏，命令原型中须包含 `IFNAME`/`IFINDEX`/`ENUMNAME`/`ENUMNUMBER`/`ENUMNEW` 之一。
- 动态帮助函数原型：`int func_help(char key, struct vty *vty, vector helpvec)`
- 在函数内通过 `malloc` 分配 `struct cmd_help_s`，填充 `name` 字段，加入 `helpvec`；内存由公共代码执行完后自动释放。
- 若一条命令有多个动态帮助参数，需借助 cmdkey 区分 `key`。

### 4.5 示例：注册 `boot-file delete ENUMNAME`
```c
DEFUN_NOBACKUP(
    boot_file_delete_func,       // 执行函数名
    boot_file_delete_cmd,        // 命令结构体名
    "boot-file delete ENUMNAME", // 命令原型
    NULL,                        // cmdkey，用默认规则
    "The file for booting\n"     // 帮助信息（与关键字一一对应）
    "Remove or obliterate\n"
    "Boot file name\n",
    get_boot_file_list_help)     // 动态帮助函数
{
    /* 业务逻辑：删除指定启动文件 */
    return CMD_SUCCESS;
}

// 在 vty_cli_reg 中注册到配置视图
void vty_cli_reg(void) {
    install_element(CONFIG_NODE, &boot_file_delete_cmd);
}
```

### 4.6 注册一条带确认命令
- 使用 `vty_isYesConfirm(vty, prompt)` 提示用户确认，返回 1 确认 / 0 取消。
- 带确认命令需用 `DEFUN_NOBACKUP` 等不备份宏定义，确认后再调用 `vty_backup_send_by_private(vty, mode)` 手动备份，备份模式须包含 `VTY_BACKUP_NO_CONFIRM`。
- 原因：避免命令行备份流程中主等待备执行结果，而备卡在确认等待导致超时失败。

## 5. 注册后台命令

### 5.1 前后台分工
- **前台（vtysh）**：接收用户输入，将命令通过 Unix Socket 转发给后台 daemon，再把结果展示给用户。
- **后台（daemon）**：真正执行业务逻辑（路由计算、接口配置等）。
- 前后台命令原型必须**完全一致**；前台负责"传话"，后台负责"干活"。

### 5.2 示例：`show ip route`
**前台（cmd_zebra.c）—— 只转发，不写函数体**
```c
DEFSH_NOBACKUP(VTYSH_ZEBRA,                // 指定后台进程 ID
               show_ip_route_cmd_zebra_plat,
               "show ip route", NULL,
               SHOW_STR IP_STR "IP routing table\n",
               NULL);

// 在 vty_cli_reg 中注册
install_global_show_command(&show_ip_route_cmd);
```

**后台（zebra_vty.c）—— 写真正的执行函数**
```c
DEFUN_NOBACKUP(show_ip_route, show_ip_route_cmd,
    "show ip route", NULL,
    SHOW_STR IP_STR "IP routing table\n", NULL)
{
    /* 遍历路由表并输出 */
    return CMD_SUCCESS;
}

// 后台初始化时注册
install_global_show_command(&show_ip_route_cmd);
```

### 5.3 前后台命令对照
| 要素 | 前台（vtysh） | 后台（daemon） |
|------|---------------|----------------|
| 宏 | `DEFSH` / `DEFSH_NOBACKUP` | `DEFUN` / `DEFUN_NOBACKUP` |
| 执行函数 | 无（仅转发） | 有（真正逻辑） |
| 命令原型 | 必须与后台一致 | 必须与前台一致 |
| 注册函数 | `install_global_show_command` | `install_global_show_command` |

## 6. 命令行支持 OVC

- 命令行启动时加载各模块 webservice 库中的注册函数，根据当前是否为 OVC0 选择不同注册函数。
- **OVC0 注册函数**：`void vty_cli_reg(void)`
- **非 OVC0 注册函数**：`void vty_ovc_cli_reg(void)`
- 每个模块可将命令注册封装在 `module_cmd_reg`，配置概览注册封装在 `module_cfg_reg`；根据 OVC0 / 非 OVC0 是否支持，在对应注册函数中调用。

**示例（user 模块，OVC 全部支持）：**
```c
void user_cmd_reg(void) { install_cmd(...); }
void user_cfg_reg(void) { cmd_summ_func_install(...); }

void vty_cli_reg(void) {        // OVC0
    user_cmd_reg();
    user_cfg_reg();
}
void vty_ovc_cli_reg(void) {    // 非 OVC0
    user_cmd_reg();
    user_cfg_reg();
}
```

## 7. 命令行支持虚拟化

### 7.1 虚拟系统类型宏
| 宏 | 含义 |
|----|------|
| `CMD_NO_SUPPORT_VSYS` | 不支持虚拟系统 |
| `CMD_VSYSTYPE_IP` | 基于 IP 的虚拟系统 |
| `CMD_VSYSTYPE_IF` | 基于接口的虚拟系统 |
| `CMD_VSYSTYPE_OVC` | 基于 OVC 的虚拟系统 |
| `CMD_VSYSTYPE_VRF` | 基于 VRF 的虚拟系统 |
| `CMD_VSYSTYPE_VT` | 基于 VLAN-TAG 的虚拟系统 |
| `CMD_VSYSTYPE_ALL` | 支持所有虚拟系统类型 |

支持多种类型时用 `|` 组合，组合类型已在 `command.h` 中给出。

### 7.2 虚拟系统命令注册函数
原有注册函数（如 `install_element`）默认 `vsystype = CMD_NO_SUPPORT_VSYS`。新增的带 `cmd_attr` 参数的注册函数：
- `install_cmd(ntype, cmd, cmd_attr)`：注册普通命令
- `install_confirm_cmd(ntype, cmd, cmd_attr)`：注册带确认命令
- `install_hidden_cmd(ntype, cmd, cmd_attr)`：注册隐藏命令
- `install_rollback_cmd(ntype, cmd, cmd_attr)`：注册配置回滚专属命令
- `install_passwd_cmd(ntype, cmd, passwd, cmd_attr)`：注册带密码命令
- `install_global_cmd(cmd, cmd_attr)`：注册全局命令

`cmd_attr` 结构体：
```c
typedef struct cmd_attr_s {
    s32 vsystype;  // 命令注册的虚拟系统
    s32 module;     // 命令所属模块
} cmd_attr;
```

### 7.3 虚拟系统配置概览注册函数
- 原型：`void cmd_summ_func_install(cmd_summ_pri_e priority, cmd_summ_pri_info_s *config_info)`
- `cmd_summ_pri_info_s` 含 `vsystype` 字段，表示配置概览支持的虚拟系统类型。
- 执行 `show running-config` / `show this` 时，只有支持当前虚拟系统的配置概览函数才会执行。

### 7.4 切换虚拟系统
- 命令：`switch-vsys vsysname`
- 在用户视图下执行，可从公共系统切换到虚拟系统，或切回公共系统（`switch-vsys PublicSystem` 或 `exit`）。
- 虚拟系统管理员直接登录后不可再切换。
- 获取当前虚拟系统 ID：`s32 vty_get_current_vsysid(struct vty *vty)`
- `switch-ovc` 只能切换公共系统的 OVC；切换被管理在虚拟系统下的 OVC 须用 `switch-vsys`；非公共虚拟系统下不支持 `switch-ovc`。

## 8. 配置概览

### 8.1 配置概览介绍
- 显示设备当前的**非默认配置**。
- `show running-config`：显示所有视图的非默认配置。
- `show this`：显示当前视图的非默认配置。

### 8.2 数据结构
```c
typedef struct cmd_summ_pri_info {
    u32 node;                   // 所在视图
    cmd_summ_module_e module;   // 所属模块
    cmd_summ_func cfg_func;     // 配置概览回调函数
    s32 daemon_id;              // 后台进程 ID，-1 表示前台
    s32 vsystype;               // 支持的虚拟系统类型
} cmd_summ_pri_info_s;
```

### 8.3 注册视图配置概览函数
**步骤一：定义优先级枚举**
- 在 `cmd_summ_pri_e` 中添加成员，命名格式 `CMD_SUMM_PRI_模块_视图`。
- 优先级决定配置输出顺序；有依赖关系的视图须放在被依赖视图之后；接口视图优先级放在一起。

**步骤二：定义模块枚举**
- 在 `cmd_summ_module_e` 的 `CMD_SUMM_MODULE_INVALID` 之前添加模块枚举，命名格式 `CMD_SUMM_MODULE_模块`。
- 在 `vty_config.c` 的 `g_config_module_list` 数组中按相同顺序添加对应字符串。

**步骤三：注册配置概览函数**
- **前台视图**：在 `vty_config_build` 中创建 `cmd_summ_pri_info_s` 结构体，调用 `cmd_summ_func_install` 注册。
- **后台视图**：前台注册时设置 `daemon_id` 为后台进程 ID、`cfg_func = NULL`；后台进程初始化时调用 `cmd_daemon_install_node(node, cfg_func, NULL)` 注册实际回调。

### 8.4 配置概览输出格式
- **配置视图**：公共框架自动加 `!`，各视图配置概览函数不需输出 `!`。
- **接口视图**：公共框架自动加 `!` 和进视图命令，配置概览函数不需输出。
- **其他视图**：配置概览函数需自行输出 `!` 和进视图命令。
- **缩进规则**：配置命令前空格数表示子视图层级（0 空格=配置视图，1 空格=一级子视图，2 空格=二级子视图）。
- 尽量避免输出以 `no` 开头的非默认命令，以免配置回滚时出现 `no no` 命令；确需以 `no` 开头的须通过 `install_rollback_element` 注册，仅在配置回滚时可执行。

### 8.5 示例（user 模块接口服务限制）
1. 在 `cmd_summ_pri_e` 中增加三个优先级（对应普通三层物理口、VLAN 口、管理口视图）。
2. 在 `cmd_summ_module_e` 中增加 `CMD_SUMM_MODULE_USER`，并在 `g_config_module_list` 中添加 `"user"`。
3. 实现配置概览函数 `vty_config_user_interface`，输出 `service forbid http` 等命令。
4. 在 `user_cfg_reg` 中为各接口视图注册配置概览函数，指定 `vsystype = CMD_VSYSTYPE_ALL`。

## 10. 命令行常见问题

| 问题 | 说明 / 处理 |
|------|-------------|
| 进入 Shell 模式 | vtysh 单进程单线程，进入 shell 会阻塞其他功能；确认所有命令行（主板/备板/主框/备框）均已退出 shell |
| 命令行挂死 | 表现为串口进入 `login:` 模式；可能原因：内存泄漏（dmesg 有 OOM/kill vtysh）、某命令实现导致；可用 gdb 分析 `/tmp/core_vtysh_*` |
| 命令行卡死 | 通常因某特殊事件未退出；用 gdb 查看 vtysh 进程停在哪个函数，正常应停在 `select` |
| 命令备份失败 | 检查对端命令行正常且不在 shell；通道不通会提示 `Connect fail, Please check hot backup setting!`；用 gdb 调试备板执行函数 |
| 带 daemon 命令执行失败 | 通常后台 daemon 执行出错，用 gdb 调试对应后台进程 |
| 常见错误提示 | `% Ambiguous command.`（命令歧义）；`% Unknown command.`（当前视图无此命令）；`% Incomplete command.`（命令不完整） |
| 重启命令行 | `kill -9 $(pidof vtysh)`；串口恢复：`/usr/bin/vtysh`；远程诊断：`/usr/bin/vtysh &` |
| 替换动态库调试 | 将编译后的 `.so` 用 tftp/ftp 下载到设备替换原库，重启 vtysh 进程即可测试新命令，无需重启设备 |

## 附录 B：生成一个简单的vty指令
![paste-1787563262928](picture/paste-1787563262928.png)
如图所示，我们可以先去cmd_vtysh.c中去使用command.h中声明的宏定义DEFUN，然后去创建一条前台命令， 随后写vty_cli_reg注册函数把命令安装到用户视图（VIEW_NODE）下。注意**这是命令注册的入口函数，名字必须是 vty_cli_reg，不能改，vtysh 启动加载你的动态库时，会主动查找这个名字的函数并调用它。相当于把你的hello world命令挂载到VIEW_NODE视图**。
vty_cli_reg 写在哪里？答案是：写在你的命令所在的 .c 源文件里，和 DEFUN 定义的命令放在同一个文件中。当 vtysh 进程启动时，会读取配置文件 /etc/vtysh.conf，逐行加载里面列出的动态库（.so 文件），并用 dlopen 方式加载动态库，然后查找并执行其中的 vty_cli_reg 函数进行命令注册。

因为 vtysh 的启动代码里写死了：加载 .so 后，用 dlsym 查找符号 vty_cli_reg 并调用。命令行启动时会逐行读取该配置文件。若读取的动态库不存在，则按照该模块被裁减或不存在处理。并用 dlopen 方式加载动态库，查找并执行 vty_cli_reg 函数进行命令注册。所以名字不能改，改了 vtysh 就找不到了。

如果你有多个命令，讲注册都集中放在 vty_cli_reg 里，比如：

~~~c
void vty_cli_reg(void)
{
    install_element(VIEW_NODE, &hello_world_cmd);
    install_element(VIEW_NODE, &goodbye_cmd);
    install_element(CONFIG_NODE, &my_config_cmd);
    install_element(INTERFACE_NODE, &my_interface_cmd);
}
~~~
编译和部署
把 mycmd.c 编译成动态库 libmycmd.so
在设备的 /etc/vtysh.conf 里加上一行：
~~~
/usr/local/web/server_files/user/libmycmd.so
~~~
重启 vtysh 进程：`kill -9 $(pidof vtysh)` 然后 `/usr/bin/vtysh` 
登录后，在用户视图下输入`show hello`，就能看到 `hello!`
