# C 指针、typedef 与字节序笔记

## 一、指针的步长

### 1.1 核心结论

> 指针的步长是由其所指的内存空间的数据类型决定的。

```c
char* p = NULL;
*p = 'a';  // 错误：对 NULL 指针解引用，程序会崩溃
p++;       // 步长 = sizeof(*p) = sizeof(char) = 1 字节
           // 等价于 (unsigned char*)p + sizeof(char)
```

```c
int* p = NULL;
*p = 4;    // 错误：对 NULL 指针解引用，程序会崩溃
p++;       // 步长 = sizeof(*p) = sizeof(int) = 4 字节
```

> 注意：步长应看 `sizeof(*p)`。在 C 语言中字符常量 `'a'` 的类型是 `int`，`sizeof('a')` 实际为 4，因此不能把步长写成 `sizeof('a')`。

### 1.2 'a' 和 4 都是立即数，正确写法

```c
// 特殊：字符串常量
char* s = "hello";   // "hello" 在常量区，s 指向常量区

// 普通：字符字面量
char c = 'a';        // 'a' 是立即数，存在栈上（或寄存器中）
char* p = &c;        // p 指向栈

// 普通：数字字面量
int n = 4;           // 4 是立即数，存在栈上
int* p = &n;         // p 指向栈
```

```c
int x = 4;                 // ① 4 存在栈上
int* p = &x;               // ② p 指向栈上的 x
*p = 5;                    // ③ 修改栈上 x 的值为 5

int* q = malloc(sizeof(int));
*q = 4;                    // ④ 4 存在堆上
free(q);
```

## 二、野指针常见场景

| 场景 | 图示 | 解决办法 |
|------|------|----------|
| 悬空指针 | `free` 后未置空，栈指针 → 已释放的堆内存 | `free(p);`<br>`p = NULL;` |
| 栈地址逃逸 | 函数返回后栈帧销毁，指针指向无效内存 | 改用堆分配（`malloc`）或传入指针参数 |
| 越界访问 | 指针运算超出数组边界，指针跳出数组范围，指向未知内存 | 严格检查数组下标和指针运算边界 |

## 三、间接赋值

### 3.1 示例

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

void getp(char** p) {
    *p = (char*)0x0011;
}

int main(void) {
    char* p1 = NULL;
    char** p2 = NULL;

    // 直接赋值
    p1 = (char*)0x11;
    p2 = (char**)0x22;

    // 间接赋值，传进去指针 p1 的地址
    getp(&p1);

    return 0;
}
```

### 3.2 间接赋值成立的三个条件

1. 定义两个变量：一个实参、一个形参
2. 将实参取地址扔给形参，建立关联
3. 通过形参取 `*` 修改实参的值

### 3.3 错误示例：只修改了副本

```c
void getp_wrong(char* p) {  // p 是 p1 的副本
    p = (char*)0x0011;      // 只修改了副本，main 里的 p1 没变
}

int main() {
    char* p1 = NULL;
    getp_wrong(p1);         // 传的是 p1 的值（NULL），不是 p1 本身
    // p1 还是 NULL，没变
}
```

> 这里就是错误的赋值：只是改变了 p 的引用，并没有改变 main 里的 p1。

## 四、const 修饰指针

| 声明 | 含义 |
|------|------|
| `const int a;` | 这个变量不能被修改 |
| `int const b;` | 这个变量不能被修改 |
| `const char* a;` | 这个指针指向的值不能修改 |
| `char* const b;` | 这个指针记录的地址不能更改 |
| `const char* const e;` | 地址和值都不能改 |

## 五、数组指针与指针数组

| 名称 | 写法 | 含义 |
|------|------|------|
| 数组指针 | `int (*p)[10]` | 强调这是一个指针，`p + 1` 会跳过整个数组长度 |
| 指针数组 | `int *p[10]` | `p[i]` 是每一个小指针，保存的是地址 |

### 5.1 示例

```c
int printArray(char** myArray, int num) {
    int i = 0;
    for (i = 0; i < num; i++) {
        // printf("%s\n", myArray[i]);
        printf("%s\n", *(myArray + i));  // 指针变量的地址加上 * 代表指针变量的值
    }
    return 0;
}

int main(void) {
    char* charArray[] = {"axv", "asdw", "sadwrfgxzcz"};
    int res = printArray(charArray, sizeof(charArray) / sizeof(charArray[0]));
    return 0;
}
```

### 5.2 如果用 malloc 分配

```c
char** charArray = (char**)malloc(sizeof(char*) * num);  // sizeof(char*) 指针地址长度
```

## 六、typedef 与函数指针

### 6.1 先看函数指针

```c
int foo(int x);
int (*p)(int);   // p 是一个函数指针
```

阅读方法：先看 `*p` 被括号包住，说明 `p` 是一个指针；再看外面 `int (...)(int)`，说明这个指针指向一个「接收 int、返回 int 的函数」。

```c
p = foo;               // p 指向 foo（函数名就是函数的地址）
int result = p(10);      // 通过指针调用，等价于 foo(10)
int result2 = (*p)(10);  // 也可以这样写，等价
```

> 如果 `int (*p)(int);` 省掉了括号，则 `int *p(int);` 是「一个函数」，名叫 p，返回 `int*`。读的时候先看括号，括号决定了这个语句的类型（包括前面的指针数组和数组指针）。

### 6.2 typedef 别名

```c
typedef int (*FuncPtr)(int);  // 定义类型名 FuncPtr
FuncPtr p;                    // 声明指针 p
p = foo;                      // 还是要把函数地址赋给 p
p(10);                        // 调用
```

typedef 省的是「类型写起来麻烦」这件事，尤其是当你要声明很多个函数指针，或者函数指针类型很复杂的时候。

**场景一：要声明一堆函数指针**

不用 typedef：

```c
int (*p1)(int);
int (*p2)(int);
int (*p3)(int);
// 每次都要写一遍 int (*...)(int)，又长又容易漏括号
```

用 typedef：

```c
typedef int (*FuncPtr)(int);
FuncPtr p1;
FuncPtr p2;
FuncPtr p3;
// 干净、不易错
```

**场景二：函数指针类型很复杂**

```c
// 不用 typedef，光写一个变量声明就晕了
int (*(*fp)(int (*)(int)))(int);

// 用 typedef 拆开，清晰多了
typedef int (*IntFunc)(int);
typedef IntFunc (*MetaFunc)(IntFunc);   // 接收 IntFunc、返回 IntFunc 的函数指针
MetaFunc fp;
```

**场景三：当参数类型或返回值类型用**

```c
// 不用 typedef：函数参数是函数指针，写法丑
void register_callback(int (*cb)(int)) { ... }

// 用 typedef：清爽
typedef int (*Callback)(int);
void register_callback(Callback cb) { ... }
```

### 6.3 typedef 与函数指针数组

```c
typedef int (*ArrayOfFunc[5])(int);
```

按照优先级从里往外拆解：

1. `ArrayOfFunc` 先和 `[5]` 结合（`[]` 优先级高）→ `ArrayOfFunc` 是含 5 个元素的数组。
2. 外面 `(* ... )` 的 `*` 与 `(...)` 结合 → 数组的每个元素是指针。
3. 再外面 `int (...)(int)` → 这些指针指向「接收 int、返回 int 的函数」。

> `ArrayOfFunc` 是一个含 5 个元素的数组，每个元素都是一个函数指针（指向接收 int、返回 int 的函数）。

## 七、回调函数

### 7.1 基本示例

```c
int callbackTest(int *a, int *b, int (*p)(int, int)) {
    return p(*a, *b);
}
```

它接收三样东西：

- `int *a` —— 普通指针参数
- `int *b` —— 普通指针参数
- `int (*p)(int, int)` —— 函数指针参数

作用：把 `*a` 和 `*b` 解引用成两个 `int`，然后作为参数，去调用 `p` 指向的那个函数，并返回结果。

被调用的函数：

```c
int addTest(int a, int b) {
    return a + b;
}
```

调用：

```c
int res = callbackTest(&a, &b, &addTest);
```

把 `addTest` 的地址（函数名 `addTest` 就代表它的地址）传给 `callbackTest`，让 `callbackTest` 去调用它。

### 7.2 核心思想

`callbackTest` 不写死「调用 addTest」，而是调用「你传进来的那个函数」。想改成乘法，只需再写一个 `mulTest`，传进去即可，`callbackTest` 一行都不用改。

我们传进去的这个函数就叫做**回调函数**：你不直接调用它，而是把它交给另一个函数，让那个函数「反过来」调用你。

```text
你（main）──把 addTest 交给──> callbackTest
        └──────<── callbackTest 反过来调用 addTest ──┘
```

### 7.3 完整示例

```c
#include <stdio.h>

// 模具：不变的
int compute(int *a, int *b, int (*op)(int, int)) {
    return op(*a, *b);
}

// 回调函数们：可以不断新增
int add(int a, int b) { return a + b; }
int sub(int a, int b) { return a - b; }
int mul(int a, int b) { return a * b; }

int main() {
    int x = 10, y = 11;

    printf("%d\n", compute(&x, &y, add));  // 21
    printf("%d\n", compute(&x, &y, sub));  // -1
    printf("%d\n", compute(&x, &y, mul));  // 110
    return 0;
}
```

> 在网络编程中，事件驱动、信号处理、定时器比较常用，因为可以把「调用什么逻辑」这件事从写死的代码里抽出来，变成运行时可替换的「参数」。

## 八、字节序与比特序

### 8.1 总览

| 层级 | 针对什么 | 叫什么 | 谁决定 | 怎么解决 |
|------|----------|--------|--------|----------|
| 字节级 | 多字节之间谁在低地址 | 字节序（大端/小端） | CPU 硬件 | `ntoh`/`hton`（运行时换字节） |
| 位（bit）级 | 一个字节内部谁占高位 | 位域填充方向 | 编译器 | 声明顺序 + 条件编译 |

### 8.2 字节序

字节序：多字节数据在内存中，字节与字节之间的排列顺序。

- `0x1234` 里，`12` 是数字的高位，`34` 是数字的低位。
- 内存地址编号小的格子叫低地址，编号大的叫高地址。

```text
0x100    0x101    0x102    0x103
┌───────┬───────┬───────┬───────┐
│       │       │       │       │
└───────┴───────┴───────┴───────┘
  ↑                         ↑
 编号小=低地址              编号大=高地址
```

> 数字的「位」和内存的「地址」是两回事。

以 `0x1234`（2 字节）存进内存为例：

| | 低地址 | 高地址 |
|---|--------|--------|
| 大端 | `12`（高位放低地址） | `34`（低位放高地址） |
| 小端 | `34`（低位放低地址） | `12`（高位放高地址） |

网络传输中需要用以下函数转换字节序：

| 函数 | 含义 |
|------|------|
| `htons` | host to network short（16 位：主机序→网络序） |
| `htonl` | host to network long（32 位：主机序→网络序） |
| `ntohs` | network to host short（16 位：网络序→主机序） |
| `ntohl` | network to host long（32 位：网络序→主机序） |

以接收为例：网络发来的数据是大端，比如 `tot_len` 的字节是 `[12][34]`。小端 CPU 直接读会读成 `0x3412`（反了）。用 `ntohs` 转换后，字节变成 `[34][12]`，小端 CPU 再读就是正确的 `0x1234`。

### 8.3 位域（比特序）

> 如果带有位段的结构体不用于映射报文内容，则不必考虑字节序问题；否则，必须分别定义不同字节序环境下的位域字段顺序。

例如 IP 头结构体（前 20 字节）：IP 协议规定前两个字段 version、ihl 共占 1 字节（各 4 位），且在网络序上 version 在前、ihl 在后。但 `hton`/`ntoh` 系列函数不能转换单个字节内的位顺序，因此在定义 IP 头结构体时，须通过编译宏判断当前系统字节序：

- 若为大端系统（`__BIG_ENDIAN_BITFIELD`）：version 字段在前
- 若为小端系统（`__LITTLE_ENDIAN_BITFIELD`）：ihl 字段在前

从而保证其顺序与网络序要求一致。

> PS：字节序只对多字节字段有意义，单字节内部不存在字节序问题。

```text
┌──────────┬──────────┐
│ 版本(4bit)│ 首部长度(4bit)│ ← 这 8 位就是第一个字节
├──────────┴──────────┤
│ 服务类型 tos (8bit)   │
├─────────────────────┤
│ 总长度 tot_len (16bit)│
├─────────────────────┤
        。。。。
├─────────────────────┤
│ 目的地址 daddr (32bit)│
└─────────────────────┘
```

Linux 内核 `iphdr` 结构体定义：

```c
struct iphdr {
#if defined(__LITTLE_ENDIAN_BITFIELD)
    __u8    ihl:4,
            version:4;
#elif defined(__BIG_ENDIAN_BITFIELD)
    __u8    version:4,
            ihl:4;
#else
#error "Please fix <asm/byteorder.h>"
#endif
    __u8        tos;
    __be16      tot_len;
    __be16      id;
    __be16      frag_off;
    __u8        ttl;
    __u8        protocol;
    __sum16     check;
    __be32      saddr;
    __be32      daddr;
    /* The options start here. */
};
```

接收时，对 `tot_len` 这类多字节字段，需要用 `ntohs(iphdr->tot_len)` 转换后才能得到正确值。

但对于「版本(4bit) + 首部长度(4bit)」这种合起来才 1 个字节的字段，读进来就是一个字节，字节序对它没有意义。

真正的问题在于：**位域的填充方向随编译环境变化**：

- 小端 GCC：先声明的占低位。
- 大端：先声明的占高位。

读进来的这一个字节，其内部 bit 的排列方式由编译器决定。假设网络上传来一个字节，IP 协议规定高 4 位是 version、低 4 位是 ihl。为了在小端机器上正确读到 version，需要把声明顺序反过来写：

```c
__u8    ihl:4,
        version:4;
```

因为小端 GCC 先声明的占低位，所以 `ihl` 落在低 4 位，`version` 落在高 4 位——这样 `iphdr->version` 读到的才是高 4 位的 version，而不是低 4 位的 ihl。
